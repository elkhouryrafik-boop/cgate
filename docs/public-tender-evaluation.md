# cgate on real public procurement notices

Generated by `bench/public/evaluate.py`. Regenerate with the two commands at
the bottom of this page.

## What this is

cgate was run, unchanged, over **134 real procurement notices** it had never
seen, published by a multilateral development bank for open international
competition. Nothing in this corpus was
written, chosen or labelled by anyone on this project.

## What this is not

**It is not an accuracy measurement.** These notices have no expert-labelled
ground truth, so there is nothing to score a finding against. This page
reports robustness, coverage and what the tool says — not whether it is right.

It is also not the tool's intended input. A procurement notice is a *summary*:
short, often unnumbered, with the conditions of contract incorporated from
elsewhere. cgate's compiler is built for a full solicitation. The numbers below
should be read as "how does it behave on a document class it was not designed
for", which is a robustness question, not a quality claim.

## Run

- Query: rows=300, offset=0
- Feed reported 423692 notices in total
- Kept 134 with at least 1500 characters of text
- Ran successfully on **134**, failed on **0**

## Did it work at all

**134 of 134 documents processed without an error.** No crash, no unhandled
exception, no timeout, on text from
50 different countries. That is the one claim on this page
that is unambiguously a pass.

## Coverage and compilation

Coverage is the share of document blocks that entered at least one check.

- Median coverage: **33.3%**
- Documents at 0% coverage: **4 of 134**
- Median commitments compiled per notice: **0**
- Notices that compiled **no** commitment at all: **77 of 134**

**This is the finding that matters.** 77 of 134 notices (57.5%)
yielded no commitments, so for those documents every downstream check had
nothing to check. It is the expected result for a summary notice with no
numbered clauses — but it means this corpus tests the front of the pipeline
far more than the checks behind it. A real accuracy claim needs full
solicitation documents, not notices.

### "Check did not run" advisories

`lint.py` raises `R000` when a document has too few numbered provisions to tell a
broken cross-reference from an unrecovered one. It reports that plainly instead
of guessing — correct behaviour. But it is modelled as a defect, so it lands in
the same list as real findings and inflates a naive count. This page counts it
separately. If the tool is to be read by anyone outside the project, `R000`
should move out of the defect list into the notes.

## Regenerate

```bash
python bench/public/evaluate.py fetch --rows 300 --os 0 --out .public-eval
python bench/public/evaluate.py run   --dir .public-eval \
       --out docs/public-tender-evaluation.md
```

The fetched notices are git-ignored (`.public-eval/`). Only this report is a shipped artefact; the manifest of notice IDs is
written next to the fetched notices and is not shipped. Contact names, addresses,
emails and phone numbers from the feed are never stored.
